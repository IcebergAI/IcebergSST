# ADR 0005 — Authentication & authorization: OIDC/SSO + RBAC

**Status:** Accepted

## Context
The web UI and API need human authentication and role-based access. Options: enterprise SSO
(OIDC/SAML), a built-in local user store, or both.

## Decision
Use **OIDC/SSO** as the identity source (e.g. Keycloak/Okta/Entra), with **RBAC** enforced in
the API across three roles:

- **admin** — manage sources, schedules, engines, suppressions, notification channels, users.
- **analyst** — run scans, triage findings, manage suppressions.
- **viewer** — read-only access to findings and scans.

Authorization is enforced by a FastAPI dependency on every route; the HTMX UI reflects the same
permissions but is never the enforcement point.

## Consequences
- Expected posture for an enterprise security tool; no local password store to secure.
- Requires an OIDC provider to operate. A local bootstrap/dev auth path may be added behind a
  flag for development, but production is OIDC-only.
- User records are keyed on the OIDC subject; roles are assigned within IcebergSST (or mapped
  from IdP groups/claims).
